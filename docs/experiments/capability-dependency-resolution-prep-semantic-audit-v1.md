# PREP semantic audit of 67 suspected redundant `requires` edges

Baseline: [PREP @ `d9adf4ca5104`](https://github.com/lehater/prep/tree/d9adf4ca51049894437f1ed3d4f74fe94936c896). Graph: **34 Capabilities / 110 edges**; 67 direct links are reachable by an alternative path. This is a **source-text-based semantic review**, not acceptance of a graph mutation. All 67 flags are assessed individually, with a test of what the intermediate Capability would need to provide. The other 43 edges are outside this specific redundancy audit.

**Results:** **55 KEEP_SUPPORTED**, **1 REMOVE_CANDIDATE**, **11 UNRESOLVED**.

**Meaning:** KEEP_SUPPORTED is a reasoned, source-grounded direct-consumption recommendation, not independent acceptance; UNRESOLVED lacks enough evidence that direct consumption is necessary or safely mediated; REMOVE_CANDIDATE has concrete written mediation evidence and a separately tested graph copy, but still requires owner confirmation. No status permits automatic writeback. The previous “66 links appear in Core, therefore keep them” rationale is expressly **rejected**; the table below does not use Core agreement to decide KEEP.

## Outcomes and limits

**REMOVE_CANDIDATE:** `prep.frontend-system-architecture → prep.application-design`. The target's Purpose explicitly says Application semantics are consumed **through** Machine Interface operations; the direct Core artifact dependency is absent, though absence is only corroboration. The concrete, fully regression-tested [single-line patch](../spec/dependency-resolution/project-pilots/prep-engineering-graph-cleanup-v1.patch) lives in Harness experimental storage. PREP has not been changed.

**UNRESOLVED cases:** `CDR-PREP-002`, `CDR-PREP-011`, `CDR-PREP-017`, `CDR-PREP-018`, `CDR-PREP-026`, `CDR-PREP-027`, `CDR-PREP-028`, `CDR-PREP-030`, `CDR-PREP-049`, `CDR-PREP-064`, `CDR-PREP-066`. These must be decided by inspecting material output needs against the actual intermediate public contract, not by absence of textual ID citations alone. **KEEP_SUPPORTED** likewise remains contestable: if an intermediate accepted contract can demonstrate complete semantic sufficiency and provider-change insensitivity, reclassify it; Core duplication is not proof.

This review was performed against pinned accepted **source texts**, without tool-enabled model mutation or self-issued Authority acceptance. The distinction between a reviewer recommendation and a project-governed decision is deliberate. No PREP `main`, Harness `main` or authoritative model was edited.
